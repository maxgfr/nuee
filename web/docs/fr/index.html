Documentation de Nuée

Nuée transforme un lien en une petite grappe privée et éphémère, faite des ordinateurs portables et des téléphones de personnes qui se font confiance. Cette page explique ce qu’elle fait, comment elle fonctionne, chaque commande, et où s’arrêtent ses garanties.

Ce qu’est Nuée

Quelqu’un lance un calcul, depuis la ligne de commande nuee ou depuis la page web, et obtient un lien et un QR code. Toute personne qui ouvre le lien rejoint l’essaim : un onglet de navigateur prête quelques cœurs, un nuee join prête une machine entière. Le calcul est découpé en tâches, les tâches sont distribuées, les résultats reviennent et sont vérifiés. Les mêmes liens transportent aussi des fichiers chiffrés, des services exposés et des sites statiques.

Le lien est la grappe. Il contient la clé publique du coordinateur, le relais pour le joindre et un secret de 16 octets. L’ouvrir vaut admission : pas de compte, pas d’inscription, aucun serveur à nous au milieu.

Nuée s’adresse à un groupe qui se fait déjà confiance : une conférence ou un atelier où le public rejoint depuis son téléphone, une classe, un labo ou une équipe avec quelques Mac et machines Linux. Le travail type se découpe en tâches indépendantes : fractales et simulations, évaluation d’un petit modèle, plongements de phrases, balayages de paramètres, entraînement de petits modèles, et échange de fichiers.

Ce que Nuée n’est pas :

  • Pas un marché. Ni paiement, ni crédit, ni jeton. Personne ne loue rien à personne.
  • Pas un moyen de faire tourner de grands modèles de langage entre pairs. Un modèle n’est jamais réparti entre appareils. Le type llm se contente de noter des réponses avec un petit modèle qui tient sur un seul appareil.
  • Pas un moyen d’exécuter le code natif d’inconnus dans votre navigateur. Les navigateurs n’exécutent que des tâches WebAssembly et WebGPU, dans un bac à sable. Les commandes natives (exec) ne tournent que sur des machines en ligne de commande dont l’opérateur a approuvé cette commande exacte d’un commit précis.
  • Ni anonyme, ni fait pour des inconnus. Les opérateurs de relais voient les adresses IP, et quiconque détient un lien est membre. Voir Sécurité et vie privée.

Démarrage rapide

Dans le navigateur

Ouvrez la page web. Rien à installer.

  1. Lancer. Choisissez Lancer, un calcul (fractale sur CPU ou GPU, évaluation skycmd, plongements, entraîner ensemble, ou votre propre module .wasm), le mode de vérification, puis Démarrer. La page affiche un lien, son QR code et six symboles. Projeter en grand agrandit le QR code pour un vidéoprojecteur.
  2. Rejoindre depuis un téléphone. Scannez le QR code. La carte d’adhésion dit qui demande (les six symboles), ce qui va tourner, ce qu’une tâche peut et ne peut pas faire, et propose combien de cœurs prêter, le GPU quand WebGPU est disponible, et l’option « Seulement sur secteur ». Un appui sur Contribuer lance la contribution ; Pause et Arrêter restent toujours accessibles.
  3. Comparer les six symboles. Ils sont dérivés de la seule clé du coordinateur. Si ceux du téléphone diffèrent de ceux de l’écran du présentateur, le lien a été remplacé en chemin : fermez la page.
  4. Regarder. La page du présentateur remplit une grille, un carré par tâche, à l’encre de chaque appareil. Un résultat rejeté est entouré de rouge dans la marge et le reste une fois refait.

Ce qui tourne dans un onglet : les tâches WebAssembly dans un groupe de Web Workers, les shaders WGSL via WebGPU quand le navigateur le prend en charge, le modèle de plongements, et le petit modèle de notation LLM sur les appareils qui ne déclarent pas moins de 4 Go de mémoire. Ce qui ne tourne pas dans un onglet : les commandes natives exec, l’épinglage, l’offre de stockage, et les téléchargements au-delà de 256 Mio. Un onglet mobile s’arrête quand il passe en arrière-plan : gardez l’écran allumé pendant la contribution.

En ligne de commande

La commande nuee tourne sous macOS et Linux. Les machines Windows rejoignent par le navigateur.

brew install maxgfr/tap/nuee

Ou compilez-la depuis une copie du dépôt (voir Building from source) :

cargo build --release -p nuee

Vérifiez la machine. selftest n’a besoin ni de clé, ni de réseau, ni de fichiers :

nuee selftest

Sur une compilation depuis les sources sans la fonctionnalité embed-tasks, elle a affiché :

✓ wasm golden: 3 golden outputs match
✓ demo modules: embedded: mandelbrot, toy-trainer, optdigits; not embedded: skycmd-arena (build with --features embed-tasks)
✓ links: job, file and pin links round-trip
✓ manifest: manifest signatures and admission proofs hold
✓ encryption: age encryption round-trips and detects tampering
✓ swarm: in-memory swarm finished 6 tasks
selftest ok

Lancez la démo de fractale :

nuee run demo:mandelbrot

Elle affiche un QR code, puis le lien et l’empreinte une fois le relais joignable, et une ligne de progression pendant que les pairs travaillent. Une exécution avec un travailleur nuee join, sur un Apple M5 avec un relais local, a affiché (QR code, début des chemins et la plupart des lignes de progression omis) :

https://maxgfr.github.io/nuee/#/J/AGG7I54LT3RYDIITQGUZBA6F…
fingerprint 🗻 🎃 💧 🎣 🍉 🥐  (compare with the screen of whoever joins)

Cette exécution utilisait --wait-peers 1 pour que le calcul attende le travailleur ; sans cette option, le coordinateur commence aussitôt avec la moitié de ses cœurs. Sur une autre machine, rejoignez avec le lien. L’argument - le lit sur l’entrée standard, pour qu’il ne finisse pas dans l’historique du shell :

nuee join -

joined with 5 slots
job 0: mandelbrot
task 9 done in 43 ms (1 so far)

Ou ouvrez le lien sur un téléphone : l’onglet rejoint le même essaim. Chaque verbe affiche du texte lisible ; ajoutez --json pour obtenir à la place un événement JSON par ligne sur la sortie standard (voir Événements NDJSON).

Fonctionnement

Le réseau : iroh

Chaque pair est un point d’accès iroh dont l’identité est une clé publique ed25519. Les connexions sont en QUIC avec TLS 1.3, et les deux extrémités s’authentifient avec leur clé : un travailleur ne parle jamais qu’à la clé de son lien. Les pairs en ligne de commande essaient d’abord un chemin UDP direct ; quand il n’y en a pas (pare-feu strict, navigateur), le trafic passe par un relais. Les navigateurs passent toujours par un relais, en WebSocket. Le relais transmet des paquets chiffrés et ne peut pas les lire.

Qui voit quelle adresse IP : l’opérateur du relais voit l’adresse de chaque pair connecté, et deux pairs en ligne de commande connectés directement voient l’adresse l’un de l’autre. Les autres pairs ne voient jamais l’adresse d’un navigateur, sauf si le présentateur active les connexions directes entre navigateurs (WebRTC) : la page du présentateur et chaque participant qui accepte voient alors l’adresse de l’autre. Les relais par défaut sont opérés par n0 pour le développement et le loisir ; pour tout le reste, lancez le vôtre avec nuee relay ou nuee serve --anchor.

Le lien est une capacité

Un lien ressemble à https://maxgfr.github.io/nuee/#/J/AGG7…. Tout ce qui suit # est le fragment, que les navigateurs n’envoient jamais au serveur web : GitHub Pages ne le voit jamais. La lettre dit de quel lien il s’agit :

LettreLienContenu
JEssaim de calculla clé du coordinateur, son relais, un secret de 16 octets
FFichierjusqu’à 4 fournisseurs, le hash BLAKE3 et la taille du chiffré, un secret d’accès de 16 octets, la clé de déchiffrement age
SSite statiquecomme F, ouvert comme un site
XService exposé, ou ancrela clé de l’hôte, son relais, un secret de 16 octets
PÉpingleun lien de fichier sans la clé : de quoi garder le chiffré, pas de quoi le lire

La charge utile est l’encodage base32 d’un octet de version, du corps encodé et d’une somme de contrôle BLAKE3 de 4 octets. Un lien coupé lors d’un copier-coller est signalé comme tronqué, un lien d’une version plus récente comme non pris en charge, et un lien abîmé comme corrompu : le message dit quoi faire. Quiconque détient un lien peut s’en servir : traitez-le comme un mot de passe, montrez-le dans la salle, ne le publiez pas.

Admission

Un pair qui rejoint prouve qu’il détient le secret sans l’envoyer : il envoie un HMAC-SHA256 des clés des deux pairs, calculé avec le secret. Le coordinateur le recalcule et compare en temps constant ; comme les deux clés y figurent, la preuve ne sert à rien sur une autre connexion. Un pair a 5 secondes pour se présenter, 64 poignées de main au plus sont en cours à la fois, et cinq preuves fausses en une minute excluent un pair pendant une minute. Avec --approve (ou « Approuver chaque appareil avant qu’il rejoigne » sur la page), chaque pair admis attend en plus un oui ou un non, et ne lit aucun blob de l’essaim avant le oui. L’adresse de relais annoncée par un pair n’est utilisée que si c’est le relais du coordinateur ou une adresse https hors des plages privées, de bouclage et lien-local, comme tout relais qu’un pair désigne pour une copie stockée ; seul un lien que vous ouvrez vous-même peut viser un relais local. Un essaim accepte au plus 256 pairs.

Calculs, tâches et baux

Le coordinateur signe un manifeste pour chaque calcul (type, hash du module, plafond de mémoire, nombre de tâches, politique de vérification, comparateur, échéance) et l’envoie à chaque pair ; les travailleurs refusent un manifeste qui n’est pas signé par la clé de leur lien. Les travailleurs disent combien de tâches ils peuvent prendre, et le coordinateur distribue des baux : une tâche, son entrée, une échéance. Un travailleur l’exécute et renvoie le résultat avec sa signature. Une tâche qui échoue (trap, mémoire épuisée, délai dépassé) est confiée à un autre pair, jusqu’à trois tentatives ; un échec n’est jamais compté comme une triche. Un bail qui dépasse son échéance est réattribué ; l’échéance est de 60 secondes par défaut, puis de trois fois la durée médiane du pair, entre 5 secondes et 10 minutes. Les résultats de plus de 1 Mio voyagent comme des blobs que le coordinateur récupère et vérifie contre leur hash. Les travailleurs appliquent leurs propres limites sur la taille du module, la mémoire, les entrées et les sorties, quoi que dise le manifeste, et gardent au plus 256 Mio de modules et de ressources entre deux baux, seulement pour les calculs qu’ils détiennent encore.

Les exécutions interrompues reprennent : les résultats déjà présents dans le dossier de sortie sont conservés, et la même commande repart là où elle s’était arrêtée (--no-resume recommence de zéro).

Vérification

Vérifier, c’est recalculer. Les tâches WebAssembly produisent les mêmes octets dans wasmtime, Chromium, Firefox et Safari : deux exécutions honnêtes se comparent octet par octet. Les types qui calculent en flottants sur un GPU ou avec un modèle se comparent plutôt avec une tolérance mesurée (voir Ce que l’on peut faire tourner).

ModeCe qui se passe
sample (par défaut)Un résultat est accepté. Le coordinateur recalcule lui-même 10 % des résultats (--sample) et glisse 3 % de canaris (--canary) : des tâches dont il connaît déjà la réponse. Les nouvelles tâches partent dans un ordre aléatoire, le numéro de tâche ne trahit donc rien, mais un canari répète une entrée : des identités qui partagent leur état peuvent la reconnaître. Les canaris attrapent les tricheurs naïfs ; la garantie, c’est le recalcul invisible.
fullChaque tâche tourne deux fois, chez deux exécutants différents, et les deux résultats doivent concorder. Deux pairs d’accord peuvent être deux identités d’un même tricheur : le coordinateur recalcule donc quand même lui-même la même part échantillonnée (--sample) et envoie des canaris ; une paire qui le contredit est bannie.
noneLe premier résultat est accepté. À réserver à des personnes et des machines de confiance.

Quand deux résultats divergent, le coordinateur exécute la tâche lui-même et son résultat tranche. Alors seulement le pair malhonnête est banni, et tous ses résultats pas encore vérifiés sont recalculés (reprise rétroactive). Un résultat dont la signature ou le hash est faux bannit aussitôt son expéditeur.

Le coordinateur garde ce rôle même quand il ne prend aucune tâche (--local-slots 0, ou « Cette page calcule aussi » décochée) : la vérification utilise sa propre capacité, distincte de sa contribution.

Quand le coordinateur ne sait pas exécuter le type (un calcul exec sans --allow-exec, du wgsl sans GPU, du llm sans --llm), personne ne peut arbitrer. Les résultats ne sont alors comparés qu’entre deux pairs, un désaccord écarte les deux, et personne n’est banni. Aucun canari n’est envoyé, puisqu’une réponse connue ne peut être qu’une réponse que le coordinateur a calculée lui-même ; les pairs d’un désaccord voient leurs autres résultats non vérifiés recalculés et ont besoin, dès lors, de deux exécutions concordantes. nuee run le dit avant le lien :

this machine cannot run these tasks, so it cannot check them: results are only compared between two peers, which one person holding the link can fake

Un résultat n’est jamais accepté sans contrôle pour faire avancer un tel calcul. Si aucun second pair capable d’exécuter le type n’est connecté, les tâches attendent, et le coordinateur le dit une fois :

2 tasks wait for a second peer able to run them: this machine cannot check Exec results and no other admitted peer can run them. Join another device with --allow-exec for this command, or restart with --verify none to accept unchecked results

Les clés des navigateurs sont créées à neuf pour chaque onglet : une seule personne qui détient le lien peut ouvrir de nombreux onglets, et « deux pairs différents sont d’accord » ne prouve pas grand-chose. La vraie garantie vient du recalcul par le coordinateur lui-même, d’un taux d’échantillonnage plus élevé, du mode full ou de --approve.

Les corrections sur le tableau

La page du présentateur montre un carré par tâche. Un carré se remplit de l’encre de l’appareil qui l’a calculé ; une tentative échouée est en pointillés ; un résultat rejeté est entouré de rouge, et le cercle reste une fois la tâche refaite et vérifiée, avec l’encre de l’appareil honnête à l’intérieur et une petite coche rouge. La marge garde une seule note rouge avec le nombre de corrections et, derrière Voir les corrections, la liste : quelle tâche a divergé, quel appareil a été banni et combien de tâches ont été refaites. Le tableau des appareils montre l’empreinte de chacun, son type (navigateur ou ligne de commande), ses tâches faites et vérifiées, son état et son temps moyen.

Calcul CPU vérifié (WebAssembly)

Le type par défaut. Un module de tâche est du WebAssembly simple, sans aucun import, avec une mémoire dont le maximum déclaré est d’au plus 1 Gio, et deux exports (nuee_alloc, nuee_run). Seule une liste fixe de fonctionnalités WebAssembly est acceptée ; le SIMD relâché, les threads, memory64 et les autres fonctionnalités qui pourraient faire diverger les moteurs sont refusés. Chaque bail tourne dans une instance neuve, avec des plafonds de mémoire, de temps, de pile et de sortie. Les mêmes octets donnent le même résultat dans wasmtime, V8, SpiderMonkey et JavaScriptCore : les tests de bout en bout vérifient trois résultats de référence dans chacun, et nuee selftest les vérifie dans wasmtime.

nuee run demo:mandelbrot --verify full

Limites : modules jusqu’à 32 Mio, entrées et sorties en ligne jusqu’à 1 Mio (au-delà, les sorties voyagent comme des blobs), au plus 32 baux par pair et 64 calculs par essaim.

Votre propre module et les fichiers de calcul

Tout module qui respecte l’ABI des tâches tourne avec un dossier d’entrées, un fichier par tâche, triés par nom :

nuee run my-task.wasm --inputs inputs/
2 tasks, verify Sample, 5 local slots, outputs in nuee-out/my-task
done: 2 tasks, results in nuee-out/my-task/results.json

Un fichier de calcul TOML décrit le reste : le type et sa table ([wasm], [wgsl], [embed], [llm], [exec], [train]), verify, deadline, [inputs] (dir, ou jsonl découpé en lots de lines_per_task), [output] (dir, merge = "concat" ou "jsonl") et [compare]. Un champ inconnu est une erreur. [wasm] assets remet des fichiers, comme un modèle ou un jeu de données, à chaque tâche (16 au plus, de 64 Mio au plus chacun) ; le module les reçoit dans une petite enveloppe avant son entrée. Le fichier examples/skycmd/dagger.toml du dépôt en est un :

nuee run examples/skycmd/dagger.toml

Il a exécuté 16 tâches et fusionné 64 000 enregistrements JSONL en un seul fichier en 50 s (compilation de débogage, coordinateur seul, 5 emplacements). L’entrée « Votre propre module » de la page accepte un fichier .wasm et des fichiers d’entrée de la même façon.

Shaders GPU (WGSL)

Une tâche wgsl est un shader de calcul exécuté par wgpu en natif (Metal, Vulkan, DX12) et par WebGPU dans les navigateurs. Le shader est analysé et validé par naga avant de toucher un périphérique ; les tampons sont plafonnés à 64 Mio par liaison et 128 Mio par tâche, et une tâche qui dépasse son échéance perd son périphérique.

nuee run demo:mandelbrot-gpu

Le coordinateur calcule aussi sur son propre GPU (il a affiché recomputing samples on the GPU Apple M5) ; seul, il a terminé en 5 s (compilation de débogage). Les travailleurs en ligne de commande n’offrent leur GPU qu’avec --gpu :

nuee join - --gpu
offering the GPU Apple M5
joined with 5 slots
job 0: mandelbrot-gpu

Les GPU ne concordent pas au bit près. Près du bord de l’ensemble, l’itération en f32 est chaotique : sur la grille de la démo, la pire tuile compte 89 pixels sur 4 096 qui diffèrent entre moteurs honnêtes. La démo accepte donc deux résultats quand au plus 50 pour mille de leurs valeurs diffèrent de plus de 2 itérations. Autrement dit, jusqu’à 5 % des pixels d’une tuile peuvent être faux sans que le recalcul s’en aperçoive. Sans importance pour une fractale ; vos propres calculs WGSL fixent leur tolérance dans [compare], et un travail dont chaque valeur doit être vérifiée relève d’une tâche wasm.

WebGPU dans les navigateurs, en octobre 2026 :

NavigateurWebGPU
Chrome, Edgeactivé par défaut sous Windows, macOS et ChromeOS depuis la 113, Android depuis la 121 ; sous Linux, selon la version et le pilote
SafariSafari 26 sous macOS, iOS et iPadOS 26

Un onglet sans WebGPU rejoint quand même et exécute les tâches WebAssembly ; il n’offre simplement pas son GPU.

Plongements

nuee embed transforme des fichiers texte en vecteurs de phrases avec all-MiniLM-L6-v2 (384 dimensions), sur le CPU en natif (candle, fp32) et avec ONNX Runtime Web dans les navigateurs (q8). Le modèle est épinglé à une révision, téléchargé une seule fois et uniquement depuis Hugging Face, et chaque fichier est vérifié contre son SHA-256.

nuee embed notes/
2 chunks in 1 tasks
checking the embedding model (downloaded once, about 90 MB)
embedding locally with all-MiniLM-L6-v2 on the cpu
1 tasks, verify Sample, 1 local slots, outputs in nuee-out/embed
2 vectors: nuee-out/embed/vectors.f32 (nuee-out/embed/meta.jsonl)
done: 1 tasks, results in nuee-out/embed/results.json

Cette première exécution a pris 16 s, téléchargement du modèle compris (compilation de débogage). vectors.f32 contient une ligne de 384 flottants petit-boutistes par morceau ; meta.jsonl dit d’où vient chaque morceau. Les deux moteurs ne produisent pas les mêmes flottants : le cosinus le plus bas mesuré entre eux sur le corpus de calibration était 0,97173, donc deux résultats concordent quand leur cosinus vaut au moins τ = 0,966 et que chaque ligne garde une norme L2 de 1 (à 0,01 près). Un vecteur falsifié aussi proche du vrai passerait. Sur la page, « Plongements » accepte un fichier .txt ou .jsonl.

Notation d’options par LLM

Un calcul llm note des enregistrements de décision : chaque enregistrement devient une invite, le modèle n’est jamais échantillonné, et seuls les scores des lettres d’option sont gardés. En ligne de commande, un travailleur offre un point d’accès local compatible OpenAI qui renvoie des log-probabilités (llama-server de llama.cpp, LM Studio, vLLM) :

nuee join - --llm http://127.0.0.1:8080

Un navigateur utilise Qwen3.5-0.8B (ONNX, q4, épinglé et vérifié par SHA-256), proposé uniquement aux appareils qui ne déclarent pas moins de 4 Go de mémoire ; la première utilisation télécharge environ 650 Mo. L’adresse du point d’accès ne vient jamais que de l’option du travailleur lui-même, jamais d’un calcul. Les scores se comparent après centrage : même meilleure option, et aucune lettre plus éloignée que 1,5 entre moteurs (0,25 suffit pour un même moteur). Il faut un serveur de modèle en marche, que la machine de test de cette page n’avait pas ; ce chemin est couvert par des tests contre un faux serveur. Le guide est docs/GPU.md.

Commandes natives (exec)

Un calcul exec lance une commande issue d’un commit Git précis, pour un travail qui demande du code natif (MLX, CUDA). C’est désactivé par défaut. Un travailleur épingle un dépôt et un commit complet de 40 caractères, puis approuve chaque ligne de commande et environnement exacts avant leur exécution :

nuee join - --allow-exec https://github.com/maxgfr/skycmd@781d4c176b2d6e301d0eeb82c69781b356505ec0

Dans un terminal, join affiche chaque commande de ce commit en entier (argv et valeurs d’environnement) et demande ; une autre commande du même commit est redemandée. Un travailleur sans terminal n’exécute que les commandes listées dans --exec-approvals FICHIER, un objet JSON par ligne ({"repo", "rev", "argv", "env"}), tels que l’invite et la note de refus les affichent. Sans --allow-exec pour le commit du calcul, join ne demande jamais. Les variables qui changent la façon dont un programme charge du code, ou quel programme ou quelle configuration il lance (LD_*, DYLD_*, *_OPTIONS, PYTHONPATH, NODE_OPTIONS, PATH, PIP_*, PAGER, SHELL… ; la liste complète est dans le modèle de menace) sont toujours refusées, et l’invite affiche chaque valeur.

Le travailleur extrait ce commit dans un dossier jetable, revérifie le commit, vide l’environnement, applique des limites de temps (extraction comprise) et des plafonds de sortie, tue tout le groupe de processus à la fin, et utilise sandbox-exec (macOS) ou bwrap (Linux) quand ils sont présents, sans réseau sauf s’il a aussi passé --exec-network. Les calculs avec gpu = true ne vont qu’aux travailleurs lancés avec --gpu, un à la fois. La commande reçoit son entrée dans $NUEE_IN et écrit son résultat dans $NUEE_OUT. nuee doctor indique si un outil de bac à sable a été trouvé.

Approuver une commande, c’est confier au code du commit les droits de votre utilisateur ; le bac à sable fait au mieux. Les navigateurs n’exécutent jamais d’exec. --exec-mirror URL=CHEMIN récupère le dépôt autorisé depuis une copie locale au lieu du réseau (machines isolées, tests) ; le commit est vérifié de la même façon. Risque accepté : une commande approuvée peut écrire dans ~/.cache et ~/Library/Caches, même dans le bac à sable, car les caches de modèles et de noyaux en ont besoin (téléchargements Hugging Face et MLX) ; elle peut donc y laisser des fichiers auxquels d’autres programmes feront ensuite confiance.

Balayages

nuee sweep exécute un fichier de calcul exec avec des entrées [[sweep]], une tâche par entrée, les args de chaque entrée ajoutés à la commande, et classe les entrées selon les métriques trouvées dans leur sortie (loss, accuracy, acc et d’autres). Un balayage sur un petit dépôt local, exécuté ici sur le coordinateur lui-même, qui approuve les commandes du fichier de balayage pour ce commit :

Fichiers et stockage durable

nuee share archive des fichiers et des dossiers, chiffre l’archive avec age avant qu’elle quitte la machine (noms de fichiers compris), et la sert jusqu’à Ctrl-C :

nuee share report.txt photos/
https://maxgfr.github.io/nuee/#/F/AEAX7AQR4ZTK…
serving 304467 bytes (encrypted) until Ctrl-C
nuee get -o dl/ -
dl/report.txt
dl/photos/a.jpg
dl/photos/b.jpg
✓ verified (BLAKE3)

Chaque octet est vérifié contre le hash BLAKE3 pendant la réception, avant le déchiffrement ; une différence termine avec le code de sortie 6. get refuse d’écraser un fichier sans --force et refuse les entrées d’archive qui atterriraient hors du dossier de sortie. La page web ouvre les mêmes liens, déchiffre dans l’onglet et affiche « Vérifié : les fichiers correspondent au lien » ; elle partage et télécharge jusqu’à 256 Mio.

nuee pin garde une copie uniquement chiffrée (il retire la clé avant de stocker quoi que ce soit) et affiche un lien d’épingle qui nomme ce nœud ; nuee serve sert tous les éléments épinglés, pin --list et pin --rm <HASH> les gèrent. Un lien de fichier ne nomme que les fournisseurs avec lesquels il a été créé : pour qu’un fichier reste accessible après le départ de celui qui le partage, utilisez le stockage durable.

Le stockage durable demande un coordinateur en marche (un nuee run qui attend, ou une ancre) et des membres qui offrent de l’espace disque :

nuee run demo:mandelbrot --local-slots 0 --wait-peers 16
nuee join - --slots 1 --store 64MiB
nuee share archive.bin --replicas 2 --on -
https://maxgfr.github.io/nuee/#/F/AEA5ON4YA5NG…
waiting for the swarm to place the copies (Ctrl-C skips the wait)
https://maxgfr.github.io/nuee/#/F/AEBTOIQRMLDW…
serving 301925 bytes (encrypted) until Ctrl-C

Donnez le second lien, le lien durable : ses fournisseurs sont les détenteurs. Les membres affichent offering 64 MiB of storage, 0 MiB in use et ne reçoivent jamais que du chiffré ; le coordinateur n’a jamais la clé non plus. Partageur arrêté et un détenteur tué, ceci a quand même fonctionné :

nuee get '<durable link>' --on '<swarm link>' -o dl3

Le coordinateur remplace une copie dont le détenteur est absent depuis 10 minutes, et met chaque détenteur à l’épreuve toutes les heures : il demande quelques plages de 1 Kio choisies à partir d’un nonce neuf (dont toujours le dernier morceau) et les vérifie contre la racine BLAKE3. Une épreuve réussie prouve que le détenteur pouvait produire ces plages à ce moment-là, pas qu’il stocke tout le fichier ; des épreuves répétées rendent probable, avec le temps, la détection d’une copie partielle. La réparation n’a lieu que pendant que le coordinateur tourne. Limites : 8 copies par blob, 1 024 blobs et 256 membres par coordinateur.

Seul le pair qui a demandé un blob peut le libérer, et chaque pair ne liste que les siens ; avec --approve, seuls les pairs que vous avez admis peuvent en demander, et jamais un pair banni. Chaque demandeur est limité à 128 blobs suivis et 64 Gio de copies, un blob qui n’a jamais obtenu de première copie est abandonné après 24 heures, et les copies libérées ou échouées d’un membre sont effacées de son disque (comptées dans son quota jusque-là). L’espace libre compte au plus 64 Gio pour choisir les membres. Une épreuve prouve la possession de plages, pas des copies indépendantes : un membre peut relayer des plages depuis une autre copie, et un détenteur du lien avec plusieurs identités peut détenir toutes les répliques.

Au lieu de copies complètes, un ensemble Reed-Solomon stocke k morceaux de données et m morceaux de parité, un par membre ; n’importe quels k reconstituent le fichier. Avec 4+2, deux membres peuvent disparaître et le stockage coûte 1,5 fois le fichier :

nuee share big.bin --erasure 4+2 --on -

La commande affiche un second lien, vers l’ensemble ; nuee get sur ce lien a récupéré l’en-tête et assez de morceaux, reconstitué et vérifié le chiffré puis l’a déchiffré, avec six membres et le partageur arrêté. La page web ouvre aussi ces liens, mais n’interroge que les fournisseurs inscrits dans le lien. Les onglets n’épinglent pas et n’offrent pas de stockage. Guide : docs/STORAGE.md.

Entraînement

nuee train exécute DiLoCo : un entraînement à parallélisme de données où les travailleurs parlent au coordinateur une fois par tour au lieu d’une fois par pas. En dix lignes :

  1. Le coordinateur détient les paramètres θ.
  2. À chaque tour, chaque travailleur reçoit θ.
  3. Il fait H pas internes de son propre optimiseur sur sa part des données.
  4. L’état de son optimiseur reste chez lui.
  5. Il renvoie Δ, sa variation sur le tour.
  6. Le coordinateur écarte les deltas qui contiennent des valeurs non finies.
  7. À partir de trois, il écarte ceux qui s’éloignent de la médiane ou la dépassent nettement.
  8. Il fait la moyenne des autres par une moyenne tronquée coordonnée par coordonnée (20 % de chaque côté).
  9. Un pas externe applique cette moyenne : SGD avec moment de Nesterov, taux d’apprentissage 0,7, moment 0,9.
  10. Un point de reprise et train.json sont écrits après chaque tour, donc une exécution reprend.
nuee train demo:train --wait-peers 2 --local-slots 0
round 1/10  loss 2.068  accepted 4  rejected 0
round 2/10  loss 1.402  accepted 4  rejected 0
…
round 10/10  loss 0.171  accepted 4  rejected 0
done: 10 rounds, model in nuee-out/toy-trainer/checkpoint-10.safetensors

Avec deux travailleurs nuee join de deux emplacements chacun, les dix tours ont pris 7 s (compilation de débogage). La démo est un petit modèle de reconnaissance de chiffres sur le jeu de données UCI optdigits ; « Entraîner ensemble » sur la page l’exécute avec des onglets de navigateur et montre la courbe de perte et la précision finale sur les chiffres de test.

L’agrégation robuste borne ce qu’une minorité peut faire en un tour ; c’est plus faible qu’un recalcul : réservez les entraîneurs exec à des personnes de confiance. Guide : docs/TRAINING.md.

Services et sites

nuee expose place un service TCP local derrière un lien ; il ne se connecte jamais qu’à 127.0.0.1 sur ce port, donc le tunnel ne peut rien atteindre d’autre sur votre réseau. Il prévient quand rien n’écoute encore :

nuee expose 18000
https://maxgfr.github.io/nuee/#/X/AG7F53MK5YWD…
fingerprint 🐸 🍯 🧊 🌙 🏏 🌻  (compare with the screen of whoever joins)
nothing answers on 127.0.0.1:18000 yet (Connection refused (os error 61)); clients will be refused until it does
exposing 127.0.0.1:18000 until Ctrl-C
nuee connect --port 18001 -
open http://localhost:18001
tunnelling to the exposed service until Ctrl-C

Chaque client prouve qu’il détient le secret du lien ; --approve demande avant chaque nouveau client, --no-http ne garde que le TCP brut. Une requête de console commence par un court message de présentation portant la preuve, vérifiée avant la lecture de la requête ; les connexions qui ne prouvent rien sont fermées après 5 secondes. Ouvrir un lien X dans la page web donne une console de requêtes : méthode, chemin, en-têtes, corps JSON. La console n’interprète jamais ce qui revient : le JSON est mis en forme, le texte affiché comme texte, le HTML comme source, le binaire proposé au téléchargement.

Comme ssh -L, nuee connect transmet toute connexion faite à son port local, quelle qu’en soit l’origine : une page web que vous visitez pendant qu’il tourne peut atteindre le service distant par DNS rebinding, sauf si le service vérifie l’en-tête Host. Prenez un port au hasard, fermez connect quand vous avez fini, et faites vérifier Host aux services exposés.

nuee connect transmet les octets tels quels : une application web ouverte sur http://localhost:<port> garde ses en-têtes, ses cookies (Set-Cookie et Cookie), ses envois de formulaire et ses appels fetch() comme si elle tournait en local. La passerelle d’une ancre, elle, retire les cookies.

nuee site publish partage un dossier qui contient un index.html sous forme de lien S chiffré, et nuee site get le télécharge :

nuee site publish ./public
nuee site get -o got -
got/public/index.html
✓ verified (BLAKE3)

La page web affiche un aperçu isolé : le document est reconstruit sans scripts, gestionnaires d’événements, cadres ni navigation, et montré dans un cadre isolé qui n’a ni script ni accès à l’origine de la page. Un site en JavaScript s’affiche comme sa coquille statique. Guide : docs/HOSTING.md.

L’ancre

Rien dans Nuée n’exige d’ancre. nuee serve --anchor, c’est nuee sur une machine qui reste allumée : un coordinateur persistant qui garde les calculs d’un redémarrage à l’autre, son propre relais, un membre de stockage pour les copies durables, et une passerelle HTTP pour les sites. Lancée en local avec un relais de développement :

nuee serve --anchor --relay-dev --relay-bind 127.0.0.1:0 --gateway 127.0.0.1:18780
anchor link (keep it secret: it carries the admin secret):
https://maxgfr.github.io/nuee/#/X/AGGEAVKJMNKR…
swarm link: https://maxgfr.github.io/nuee/#/J/AGGEAVKJMNKR…
fingerprint ⛽ 🐍 🍳 🐧 🍼 🍅
gateway: http://127.0.0.1:18780
relay: http://127.0.0.1:55873

Confiez-lui un calcul et récupérez les résultats ; le calcul continue sans la machine qui l’a soumis :

nuee --relay http://127.0.0.1:55873 run demo:mandelbrot --anchor - --follow --out results
job 1 runs on the anchor 8c405549…a9b9; it keeps running without this
done: 257 files in results

Un site publié avec --on <lien de l’ancre> est servi par la passerelle à /s/<id>/. Cela remet la clé de déchiffrement à l’ancre : son opérateur peut lire le site. Chaque réponse de la passerelle porte Content-Security-Policy: sandbox, X-Content-Type-Options: nosniff, Referrer-Policy: no-referrer et Cross-Origin-Resource-Policy: cross-origin ; --gateway-scripts autorise les scripts, toujours isolés et jamais de même origine. La passerelle ne relaie jamais le Set-Cookie d’un service, remplace les en-têtes Forwarded, X-Forwarded-* et X-Real-IP du visiteur par un X-Forwarded-For portant l’adresse qu’elle a vue, et laisse à une requête 10 secondes pour son en-tête et 30 de plus pour son corps. Servez la passerelle sur un nom d’hôte qui lui est propre. La politique de ressources vaut cross-origin parce qu’une page isolée a une origine opaque : toute valeur plus stricte ferait bloquer par les navigateurs les feuilles de style, scripts et images du site lui-même.

En production, le relais utilise --relay-hostname et --acme-contact pour un certificat Let’s Encrypt, ce qui demande un vrai domaine et les ports 80 et 443 ; --relay-token-file, --relay-max-conns et --relay-rate le restreignent, et --allow ou --allow-file limitent l’essaim aux identifiants de pairs listés. Un navigateur passe le jeton du relais dans l’URL : il apparaît donc dans les journaux d’accès du relais. Le dépôt fournit un fichier Docker Compose et une unité systemd ; installation, ports du pare-feu, sauvegardes et mises à jour sont dans docs/ANCHOR.md.

skycmd

skycmd entraîne de petits modèles de décision de vol ; c’est la première vraie charge de travail pour laquelle Nuée a été construite.

  • Évaluation (demo:skycmd) : le simulateur de skycmd compilé en WebAssembly joue à quatre jeux avec le modèle s3-pico, 4 jeux × 4 graines × 10 épisodes, seuil de décision 0,6. Le modèle est vérifié contre son hash BLAKE3 avant usage, et les résultats sont les mêmes octets sur chaque moteur : la vérification est exacte. La page la propose sous le nom « Évaluation skycmd ».
  • Enregistrements DAgger (demo:skycmd-dagger) : le modèle joue, l’oracle du jeu étiquette chaque état visité, et les 64 000 enregistrements sont fusionnés en un seul fichier JSONL pour l’affinage.
  • Étiquetage par un modèle enseignant (examples/skycmd/label.toml) : un calcul exec qui note 80 000 enregistrements en 40 lots sur des Mac avec MLX, comparé avec une tolérance car MLX diffère légèrement d’un Mac à l’autre.
  • Entraînement DiLoCo de s4-micro (examples/skycmd/train-s4.toml) : un entraîneur exec, 40 tours × 500 pas internes sur 4 travailleurs.

Sécurité et vie privée

ProtégéComment
Les machines des contributeursWebAssembly sans imports, liste fixe de fonctionnalités, plafonds de mémoire, de temps et de sortie appliqués par le travailleur lui-même ; WGSL validé avant usage ; exec désactivé sauf autorisation
L’intégrité des résultatsrésultats signés, recalcul par le coordinateur, canaris, bannissements avec reprise rétroactive ; tolérances annoncées là où les flottants diffèrent
À qui l’on parlela clé du coordinateur est dans le lien et authentifiée par TLS ; les manifestes sont signés ; six symboles à comparer à voix haute
Le contenuQUIC chiffré de bout en bout, y compris à travers les relais ; fichiers chiffrés avec age avant de partir ; épingleurs, membres de stockage et relais ne voient que du chiffré
L’origine webpolitique de sécurité du contenu stricte, Trusted Types, pas d’innerHTML, pas de CDN, rien de secret dans le stockage du navigateur, contenu hébergé jamais rendu dans l’origine

Non protégé, par conception :

  • Qui détient un lien est membre. Quiconque voit un lien peut utiliser ce qu’il accorde.
  • L’opérateur du relais voit les adresses IP et les volumes, jamais le contenu. Les relais n0 sont faits pour le développement et le loisir.
  • WebRTC, quand le présentateur l’active, montre au présentateur et à chaque participant qui accepte l’adresse IP de l’autre. C’est désactivé par défaut, et l’interrupteur comme la carte d’adhésion le disent.
  • Un coordinateur choisit ce que ses travailleurs exécutent. Une tâche qui reste dans ses limites peut quand même consommer tout le temps CPU accordé ou renvoyer n’importe quoi.
  • Les travailleurs Sybil. Les identités de navigateur sont gratuites : un bannissement coûte à un tricheur une reconnexion ; en mode sample, un résultat faux qui n’est ni échantillonné ni un canari est accepté, et en mode full aussi un résultat faux sur lequel deux identités du tricheur s’accordent, s’il n’est pas échantillonné. Ce qui les arrête, c’est le recalcul du coordinateur lui-même.
  • Les tolérances laissent de la marge à un travailleur malhonnête : 5 % d’une tuile de fractale GPU, un cosinus de 0,966 pour les plongements, un écart de logits pour les notes LLM.
  • L’empreinte fait 48 bits : elle résiste aux collisions fortuites, pas à une recherche acharnée contre une empreinte donnée.

Le modèle de menace complet, avec le code qui met en œuvre chaque protection, est docs/THREAT-MODEL.md ; le format sur le réseau est docs/PROTOCOL.md.

Dépannage et limites

error: relay unreachable: check your connection or pass --relay <url> (see `nuee relay`)
Code de sortie 3. Aucun lien n’est affiché tant que le relais ne répond pas, dans un délai de 10 secondes (NUEE_ONLINE_TIMEOUT_MS). Vérifiez la connexion, ou indiquez un autre relais avec --relay. La page dit « Impossible de joindre le relais. Vérifiez votre connexion et réessayez. »
error: the coordinator ended the swarm
Code de sortie 8 pour nuee join : le coordinateur s’est arrêté (son propre run sort avec 7 quand il est interrompu, en gardant les résultats terminés pour une reprise). La page dit « L’essaim est terminé. » ou, pour un partage dont la source a disparu, « Cet essaim ou ce partage n’existe plus (ou son hôte est hors ligne). »
error: the link looks truncated; copy it again in full
Code de sortie 2. Le lien a été coupé lors d’un copier-coller ; la somme de contrôle à sa fin ne correspondait pas. Les QR codes et - sur l’entrée standard évitent ce problème. Un lien d’une version plus récente donne link version … is not supported; update nuee.
« Ce navigateur est trop ancien pour Nuée (il manque le SIMD de WebAssembly, comme dans Safari avant 16.4). »
Les tâches ont besoin du SIMD de WebAssembly. Mettez le navigateur à jour ou utilisez-en un autre.
« Ce navigateur n’exécute pas WebAssembly. Sur iPhone ou iPad, le mode Isolement le désactive… »
Le mode Isolement désactive WebAssembly. Autorisez le site dans les réglages du mode Isolement, ou utilisez un autre appareil.
… tasks wait for a second peer able to run them …
Le coordinateur ne peut pas vérifier ce type lui-même, et un seul pair connecté sait l’exécuter. Faites rejoindre un second appareil qui le peut (avec --allow-exec, un GPU, --llm), ou relancez avec --verify none pour accepter des résultats non vérifiés. Sur la page : « 1 tâche attend un second appareil capable de l’exécuter, pour la vérifier. »
Pas de tâches GPU, ou --gpu: no usable GPU adapter on this machine
Un travailleur en ligne de commande ne prend des tâches wgsl qu’avec --gpu, et il lui faut un adaptateur utilisable (nuee doctor l’affiche). Un onglet n’offre son GPU que si WebGPU est disponible ; regardez chrome://gpu ou about:support.
error: provider unreachable (…): is the sharer still online?
Code de sortie 3 pour nuee get : aucun des fournisseurs nommés dans le lien ne le sert. Demandez au partageur de relancer nuee share, ou utilisez un lien durable avec --on <lien de l’essaim>.
error: dl/report.txt already exists (pass --force to overwrite)
nuee get n’écrase jamais rien sans --force.
native commands are disabled on this node (see --allow-exec)
Le travailleur n’a pas épinglé le repo@rev du calcul ; l’invite de join affiche les deux.
job N runs a native command this machine has not approved
Le travailleur n’a pas de terminal pour demander et la commande n’est pas dans son fichier --exec-approvals. La note affiche la ligne à ajouter ; rejoignez après l’avoir ajoutée.

Les limites, franchement

  • Les opérateurs de relais voient les adresses IP des navigateurs ; WebRTC, quand il est activé, les montre au présentateur et aux participants.
  • Les relais publics de n0 sont faits pour le développement et le loisir.
  • Les clés des navigateurs sont éphémères : l’accord entre deux pairs navigateurs ne prouve pas grand-chose.
  • Les onglets mobiles s’arrêtent en arrière-plan.
  • La page web garde les fichiers en mémoire : 256 Mio au plus à partager ou à télécharger.
  • Les entraîneurs natifs ne sont pas recalculés ; les résultats GPU, de plongements et LLM sont comparés avec des tolérances.
  • Il n’y a pas de binaire Windows ; les machines Windows rejoignent par le navigateur.
  • Nuée s’adresse à des groupes qui se font assez confiance pour partager un lien. Ce n’est pas un marché ouvert.
